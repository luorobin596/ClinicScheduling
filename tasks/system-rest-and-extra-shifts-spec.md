# 系統排休、補班與公平性報告規格

狀態：已依確認規則完成本機實作，待 TEST 試算表及大量模擬驗證。

## 目標與範圍

在分配正常班之前，替休假意願不足額的正職補上系統排休，讓初排使用一致的休假基準。正常排班定案後，將剩餘骨科名額開放給願意多上班的人，在系統排休日補班。正式班表保留補班結果，公平性及報告保留補班前的基準。

## 1. 額度與日期

- 當月週六加週日的天數為基本休假天數。週日固定全院休診，扣除這部分後，正職個人排休額度等於當月週六天數 × 8 小時。這是初排用的額定休假。
- 國定假日及額外診所休診另按 `System_Configurations` 的 `closed_dates` 處理。合併所有啟用列的 C～E 欄並以日期去重。與週日重疊時只有一個休診日，與週六重疊時該日也關診，個人額定排休仍按當月週六天數計算。個人排休可安排在其他營業日。
- 只有營業日上的個人排休計入額度。全天休計 8 小時，指定單班且其餘時段皆休計 4 小時，指定雙班計 0 小時。休診日期上的意願不重複折抵。未提交或無法判定的意願列為資料待確認。
- 例如 2026 年 11 月有 4 個週六、5 個週日。每人個人額定排休 32 小時。若另有平日國定假日，當日全院休診，個人仍在營業日安排 32 小時。
- 既有 `closed_dates` 可關閉指定的平日或週六。正式試算表尚待以 TEST 環境核對。

## 2. 正常排班與系統排休

1. 建立營業日曆，讀取個人意願並確認固定班及小兒固定／代班。
2. 計算每人的休假缺額 `max(0, 額定排休時數 − 個人已排休時數)`。每滿 8 小時缺額抽一個整日，不足 8 小時的餘額不抽休。例如額定 32 小時、已排 28 小時者抽 0 天，已排 24 小時者抽 1 天，已排 20 小時者也抽 1 天。初排預排工時扣除個人已排休與實際加入的系統排休時數。
3. 以員工與日期記錄系統排休來源。只抽營業日，排除該員工已有休假意願、指定班、小兒固定或代班的日期。抽選使用可重現的種子，並檢查全體同日安排是否可行。若抽到無法完成最低覆蓋或正常排班的組合，嘗試其他日期組合。若仍無法完成，列出人員、缺額及限制，供管理者處理。
4. 系統排休在正常排班期間視為全天不可排，平日工作日修補也跳過該員工當日。正常排班依既有順序完成初排、最低覆蓋修補、平日工作日修補及公平性調整，驗證後保存補班前的工時及公平性快照。

## 3. 公平性與剩餘名額

公平性依序比較月非自願單節公平性 → 月工時達成率 → 個人每週非自願單節集中程度 → 每週 AC → 每週 BC／AB。每週集中程度先比較全體員工中最高的個人單週次數，同分再比較各人各週次數的平方和。週界沿用週日至週六，含月初月末短週與營業週六。自願單節另外統計。

月工時達成率以補班前實排工時除以補班前預排工時。預排工時依營業日及正常排班採用的個人休假和系統排休計算，在正常排班搜尋及補班期間固定。正式報告的公平性數字，包括單節及每週班型，使用補班前快照。

- 個人排休低於額定即視為願意補班。補班只使用正常排班完成後的剩餘骨科名額，且僅限該員工的系統排休日。缺額不足 8 小時者雖視為願意補班，但沒有系統排休日可供這個階段安排。員工自己的休假與正常排班已排定的班次受保護。
- 先安排可同日補兩班的合法組合，再補單班。同等合法候選若競爭同一名額，優先給補班前工時達成率較低的人。候選完全相同時使用可重現順序。補班完成後保留最終班表，初排公平性快照固定。
- 額定休假只用於初排。補班後可低於額定休假。沒有可補名額就保持空班。補班仍須通過班別人數上限、每日最多兩班、固定班、跨科、骨科最低覆蓋及週六最大可行 AB 等檢核。

## 4. 班表與報告

- 員工×日期仍使用現有班表儲存格。個人意願沿用淺藍色。系統排休日使用淺綠色 `#d9ead3`，未補班時留白，補班後顯示正常班別代碼並保留綠底。後端按月份、員工及日期保存系統排休與補班來源，重匯出可重建，重排時清除舊的系統排休底色。
- 正式寄信沿用現有「實際工時」欄。補班前 152 小時、補班 8 小時時，顯示 `152 + 8`。加號後依實際補班工時顯示，沒有補班只顯示 `152`。若預排工時為 168 小時，這筆資料的公平性達成率為 `152 / 168`，最終實際出勤為 160 小時。
- 現有正式信件和測試摘要各新增一張「每人每週單節班」表。正式信件列員工、週日期區間、補班前的自願及非自願單節實際次數。400／5,000 組報告按員工、月份和週別列跨成功樣本平均與有效樣本數，完整週與短週分開彙總。零次計入平均，失敗仍列入成功率統計。

## 5. 驗收

| 情境 | 預期 |
| --- | --- |
| 平日休診、週日重疊、多筆休診設定 | 所有啟用日期合併去重，休診日無班也不進抽休。 |
| 休假已滿、缺 4、8 或 12 小時 | 分別抽 0、0、1、1 天。三種缺額都視為願意補班，補班日期限系統排休日。個人休假及固定班保留。 |
| 多人同日被抽休導致最低覆蓋不可行 | 尋找其他抽休組合，無可行結果時回報具體限制。 |
| 系統排休日整天空班 | 正常排班及平日工作日修補保留空班。 |
| 有雙班、單班或無剩餘名額 | 依序補合法雙班及單班，無名額則留空。允許補班後休假低於初排額定。 |
| 兩人競爭同一補班名額 | 同等合法且同為雙班或單班時，補班前工時達成率較低者優先。 |
| 月單節與工時達成率同分 | 每週 `1、1、1、1` 優於 `4、0、0、0`。 |
| 補班前 152 小時、後補 8 小時 | 報告顯示 `152 + 8`，公平性使用 152 小時及補班前班表。 |
| 重匯出及重排 | 系統排休來源、班別和綠底一致，過期綠底清除。 |

正式程式位於 `GAS/`，單元與假試算表整合驗證位於 `tests/`。本機回歸命令為 `TZ=Asia/Taipei node --test tests/*.test.cjs`。大量模擬依 [現有操作流程](../tests/EXPANDED_TESTING.md) 執行。比較時使用同批輸入，另以休假額度足夠及不足的配對案例，驗證初排、覆蓋修補、工作日修補、正常排班定案與補班各階段的工時及單節變化。

## 6. 儲存與測試入口

- 系統排休名單保存於 `Schedule_Output` 同日骨科 A 列的 P 欄備註。補班沿用對應員工的來源欄，標示 `SYSTEM_REST_EXTRA`。H 欄保留個人休假名單。
- 抽休最多嘗試 32 組，並受正常排班的時間預算限制。抽休重試到限會回報涉及的員工及最近一次排班失敗原因。
- 既有 400 組輸入可用 `TZ=Asia/Taipei node tests/evaluate-system-rest-400.cjs --out <新的輸出資料夾>` 重跑，資料來自版本庫的歷史封存。快速檢查可加 `--limit-per-group 1`。
