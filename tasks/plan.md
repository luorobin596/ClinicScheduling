# 每日最低骨科覆蓋與公平性調整：待審閱方案

狀態：僅規劃，未修改正式引擎。保留已採用的每兩週正反序輪轉。

## 流程

固定班與休假 → C / AC / A → B → 平日單節班統計 → 週六 → 最低骨科覆蓋修補 → 公平性調整 → 完整驗證 → 儲存。

## 不可違反的條件

- 尊重所有指定休假及指定上班，個人指定 AB/BC/AC 均鎖定，不因零扣假額度而可修改。
- 小兒固定班與代班結果鎖定；同一時段員工不能跨站重複。
- 每人每天最多兩班。
- 骨科平日 A/B/C 各最多 3 人；週六 A 最多 3 人、B 最多 2 人，使用現有設定值。
- 平日至少兩位不同骨科員工，且骨科 ABC 各至少一人；週六至少一位骨科員工。
- 小兒不計骨科最低人力；不強迫各班補滿至上限，保留兼職缺額。

## 意願與鎖定來源

逐人來源與鎖定的詳細前置規格見 [staff-assignment-provenance-spec.md](staff-assignment-provenance-spec.md)。

從當月 requests 的 fixed/off 及初始化完成後的 PEDS 指派建立 staff/date/shift/station 鎖定集合，不能依賴 slot.source，因現有 source 為多人共用欄位，後續排班會覆寫。

全天休 ABC off；半天休一個 fixed、其餘 off；指定雙班兩個 fixed、其餘 off。只有個人選擇的一班 fixed 加另外兩班 off（週六只檢查可營業時段）的單節班屬自願。PEDS 來源為固定不等於自願；若本人確實選半天休且與實際單節相符，仍按本人意願排除。

## 階段一：最低覆蓋修補

1. 計算每個營業日缺少的骨科時段及不同員工人數不足量，先處理候選人少的日期，平手按日期。
2. 對缺少的時段搜尋可移動的自動班：同人同日改班、同日兩人交換、跨日移動或交換。移出時段不得因此無人，原本達標日期不得失去最低人數。
3. 單一步驟無法修補時允許短的兩步交換，在副本上驗證整個調整組合，而非輸出中間狀態。
4. 在可行交換/移動候選中選公平性較好的結果；若無法改善覆蓋，才搜尋新增一班。新增也必須通過所有鎖定、每日上限、同時段占用與骨科上限。
5. 每次接受的調整須嚴格改善總覆蓋缺失，不增加任何原本已覆蓋的時段缺失，不犧牲原本達標日。修補階段可能需要接受可量化的公平性代價，明確記錄。
6. 找不到候選時保留原班表與診斷，不寫出不合格班表。區分明確輸入衝突與有限搜尋未找到方案；後者不可宣稱無解。

月底 B target=0 屬原始配額策略；修補不受個人軟配額阻擋，但仍受所有硬條件限制，不將所有人的 B 目標一律改成 1。

## 階段二：公平性調整

在最低覆蓋全部達成後，搜尋未鎖定骨科指派的轉移與交換。維持修補後每個日期/班別/站別的排班人數及總班數，不藉刪班降低工時差距，也不為平衡而任意增加工時。只接受嚴格改善公平性向量的完整候選。

建議優先序（待使用者審閱）：

1. AC 與 BC 負擔分別平衡：先比較兩種班型中最嚴重的差距，再比較兩者總差距與離散程度，避免互相抵銷。
2. 非自願單節班與 AB 機會平衡：分別列出，不把自願半天休的單節班算成負擔。若優先序有取捨，報告顯示各項變化。
3. 總工時差距。
4. 修改班次數量與決定性平手規則。

月統計含週六，個人工作統計包含 PEDS；另報完整週平日的 AC/BC/AB，不對短週強制 1/2/2 配額。第一版以整月公平性為主要評分，完整週作次要診斷，避免彼此衝突的週/月硬配額。固定班限制需在報告呈現，但不從負擔統計刪除。

採有限局部搜尋，設定候選評估與時間上限、固定排序及平手決策，記錄停止原因。不能宣稱全域最佳或保證人人完全相同；實際界限待本機耗時測試後確定。

## 驗證與輸出

- 以相同 100 組 human-leave v3 意願做初始班表、只修覆蓋、再調公平性的三段比較。
- 先確認每段班表遵守鎖定與上限；覆蓋修補成功的班表，後續公平性調整不得破壞最低覆蓋或更改各時段人數。
- 公平性階段評分不得比修補完成時更差；新舊最終各指標允許存在取捨，逐項披露，不能宣稱全部改善。
- 案例涵蓋：11/30 無休假缺 B、兩人同 AB 缺 C、兩人不同班型已達標、週六零人、有空位可直接補、需交換且不可拆固定班、小兒代班形成單節、不可行或搜尋未成功。
- 報告列出輸入衝突、修補成功、未修補原因、候選/時間上限及每次調整前後結果；失敗不可從成功率中消失。
- 純記憶體比較，不寫正式試算表；最終驗證成功後才進既有 saveToScheduleOutput。

## 預計修改範圍

主要為 scheduling_engine.js 及 tests 的共用評分、覆蓋與模擬工具；必要時 Config_system.js 加搜尋設定。保留目前 Sheet 欄位結構與前台呼叫介面，不改為讀取 Sheet REQUIREMENT、不做跨月輪轉、不做兼職排班。

## 任務順序

1. 建立不可變意願鎖定與一致的公平性統計，修正引擎/測試的單節班定義落差。
2. 建立共同硬條件驗證與候選調整的試算/回復機制。
3. 實作最低覆蓋修補與未成功診斷。
4. 實作保持人數的公平性局部交換。
5. 接入儲存前驗證，重跑同批資料及回歸案例、量測執行時間。
